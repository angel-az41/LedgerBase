# LedgerBase — Accounting Demo

## Overview

This document demonstrates LedgerBase's double-entry accounting
workflows using a fictional consulting company, ABC Consulting LLC.

The scenario covers eight journal entries dated October 1–17, 2026.

The goal is to demonstrate that LedgerBase correctly:

- Creates and posts balanced journal entries.
- Assigns business-specific journal references.
- Protects posted financial records from modification.
- Applies accrual accounting principles.
- Recognizes revenue and expenses in the correct periods.
- Tracks receivables, payables, and unearned revenue.
- Distinguishes operating expenses from capital expenditures.
- Generates consistent financial statements.

All transactions and amounts are fictional demonstration data.

This is a manual demo walkthrough, not an automated database seed.

## 3. Journal Entry Workflow

Each demonstration transaction follows the same workflow:

1. Select ABC Consulting LLC.
2. Open Transactions.
3. Click New Journal Entry.
4. Enter the accounting date and description.
5. Select the debit and credit accounts.
6. Enter the journal amounts.
7. Verify that total debits equal total credits.
8. Save the transaction as DRAFT.
9. Open View Details and review the transaction.
10. Post the verified journal entry.

LedgerBase assigns a journal reference automatically when a
transaction is created.

For a fresh business, the expected sequence is:

JE-0001, JE-0002, JE-0003, and so on.

References are unique within each business, not globally.

Internal PostgreSQL transaction IDs remain globally unique
and are used for API operations.

Only POSTED journal entries affect financial statements.

Once posted, protected financial records cannot be edited
or deleted through normal transaction operations.

## 8. Database Verification

After posting all eight journal entries, verify their
journal references, statuses, and debit/credit totals.

The following query is read-only.

Replace the business ID with the ID of the demo business
in your development database.

For the original local demo, ABC Consulting LLC had
business ID 2.

```sql
SELECT
    'JE-' || LPAD(j.journal_number::text, 4, '0')
        AS journal_reference,
    t.transaction_date,
    t.description,
    t.status,
    COALESCE(SUM(e.debit), 0) AS total_debits,
    COALESCE(SUM(e.credit), 0) AS total_credits
FROM transactions t
JOIN transaction_journal_numbers j
    ON j.business_id = t.business_id
   AND j.transaction_id = t.id
LEFT JOIN ledger_entries e
    ON e.business_id = t.business_id
   AND e.transaction_id = t.id
WHERE t.business_id = 2
GROUP BY
    t.id,
    t.transaction_date,
    t.description,
    t.status,
    j.journal_number
ORDER BY j.journal_number;
```

Expected results:

- Eight journal entries.
- References JE-0001 through JE-0008 in a fresh business.
- Every transaction has POSTED status.
- Every transaction has equal debit and credit totals.

The actual internal transaction IDs may differ.

## 9. Accounting Integrity Checks

The demonstration validates several important
financial data integrity requirements.

### Double-Entry Bookkeeping

Each transaction must contain matching total debits
and total credits.

### Draft and Posted Lifecycle

Transactions are created as DRAFT and must be
explicitly posted before affecting financial reports.

### Posted Transaction Immutability

Posted financial records are protected against
subsequent modification.

### Business-Specific Journal References

Each business maintains its own journal number sequence.

Two businesses can independently have JE-0001 while
using different internal transaction IDs.

### Accrual Accounting

Revenue and expenses are recognized when earned or
incurred, rather than solely when cash changes hands.

### Financial Statement Reconciliation

The following results must be mutually consistent:

- Trial Balance debit and credit totals: $36,000 each.
- Income Statement net income: $4,800.
- Balance Sheet total assets: $32,800.
- Balance Sheet total liabilities and equity: $32,800.
- Balance Sheet balancing difference: $0.

## 10. Scope and Limitations

This demonstration exercises the general ledger and
financial reporting workflows.

It does not yet implement:

- Customer-linked invoice reconciliation.
- Vendor-linked bill payment allocation.
- Automated fixed-asset depreciation.
- Production authentication and authorization.
- Automated initial demo-data seeding.
- Importing transactions from external accounting files.

These are separate potential enhancements.

All financial information is fictional, and LedgerBase
is currently a development portfolio application rather
than production-ready accounting software.
